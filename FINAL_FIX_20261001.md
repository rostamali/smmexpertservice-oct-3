# Final fixes — 2026-10-01

## Storefront payment UI
- Added a source-owned Shadcn-style searchable combobox used by both NOWPayments and PayGate without adding a new runtime dependency.
- NOWPayments currency rows render in the requested compact format: logo, ticker, `[network]`, then the currency name.
- The storefront defensively filters out any crypto entry unless both payment and payout availability are explicitly true.
- PayGate now uses a provider selector first, followed by a separate `Pay Now` button that creates the payment session only after a provider is selected.
- PayGate provider entries preserve custom title/image, converted amount, minimum/availability state, and loading feedback.
- Removed old inline card-selection behavior for PayGate while keeping the existing page layout and visual system intact.

## Verification
- Updated the stale payment verification script so it validates the current customized storefront rather than the removed legacy PaymentHero component.
- All storefront source verification suites referenced by `npm run verify` passed in this workspace.
- TypeScript/TSX syntax transpilation was run across both projects with zero syntax errors.

## Crypto selector follow-up
- NOWPayments no longer auto-selects the first available cryptocurrency when the payment picker first opens.
- The closed combobox now shows `Select Cryptocurrency` until the customer explicitly chooses a currency.
- Existing generated NOWPayments payments still retain their current currency when returning to the change-currency flow; no first-item fallback is used.
- PayGate provider selection remains unchanged and continues to show `Select payment provider` until a provider is chosen.
- Added a payment UI regression check for the no-auto-selection behavior.
